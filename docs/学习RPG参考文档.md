## 0. 设计哲学与设计目的

> 一份关于"学习如何学习"的个人实验

### 0.1 核心信条：学习的"白箱化"

传统学习是一个黑箱。你投入时间，产出某种"感觉"——觉得自己掌握了、觉得自己退步了、觉得今天效率很高。但这些都是主观判断，缺乏可验证的量化锚点。

**学习RPG的根本哲学是：学习过程可以被量化，而且这种量化能反过来指导学习本身。** 每一次刷题、每一次背诵、每一次考试，都是关于"你如何学习"的实验数据。系统不告诉你"应该学什么"，而是告诉你"你学得怎么样"，让你自己做出更明智的决策。

这不是一个教学系统，而是一个**认知镜面**——它试图照见你学习过程中那些肉眼看不见的变化：一个知识点的记忆是如何衰减的、一个技能是如何从"入门"走向"精通"的、今天的专注投入是否真的转化为了长期记忆。

### 0.2 数据溯源闭包原则

系统中任何非用户直接输入的数值，都必须能从历史记录中推导得出。

- 不存在"天降神参"——所有算法权重都由用户的数据决定
- 不存在"预设学科难度"——学科难度的评估完全来自用户在该学科的遗忘速率和正确率表现
- 不存在"固定的每日学习上限"——上限由用户过去30天的实际学习容量动态计算

冷启动时可以使用基于认知科学文献的弱先验（如初始半衰期3天、初始能力值50），但这些先验被设计为可退化的——数据积累后，先验的权重指数级下降，最终完全被个人数据替代。

### 0.3 低输入负担原则

一个学习系统如果要求用户花大量时间记录，就会陷入"为了记录而学习"的悖论。系统设计遵循以下优先级：

1. **能不输入的，绝对不让用户输入**——通过教辅联动、章节映射、时间推断，自动补全90%的字段
2. **能推断的，绝对不要求精确**——通过个人习惯学习、正确率偏差微调，在缺失数据时做出合理估计
3. **能从历史学的，绝对不预设固定值**——订正时间占比、最优学习时长、最佳复习时机，全部从用户数据中学习

**目标：** 用户每日记录投入不超过30秒。理想状态下，5秒完成一条记录。

### 0.4 自适应而非预设

学习RPG采用自适应模型——从用户的数据中学习用户的规律。

- 半衰期不是固定的1.5天，而是从用户每次复习的间隔和正确率中反推的个性化中位数
- 学科难度不是预设的标签，而是从各科知识点的实际半衰期对比中动态计算
- 每日容量不是500XP的硬编码，而是从过去30天学习时长的80分位数自动得出
- 订正时间占比不是20%的猜测，而是从用户偶尔明确标注的数据中学到的个人习惯

**系统越用越懂你，因为每一次记录都在训练它。**

### 0.5 认知科学驱动

所有核心算法都有认知心理学文献的支撑：

- **遗忘曲线**：基于艾宾浩斯1885年实验的指数衰减模型（Murre & Dros, 2015 复制验证）
- **间隔重复最优时机**：复习触发阈值设定在保留率降至80%时（Wozniak & Gorzelanczyk 数学推导）
- **测试效应**：检索练习比重复学习更有效（Roediger & Karpicke, 2006）
- **必要难度理论**：Bjork提出——学习过程中付出的认知努力越大，长期记忆越牢固
- **最近发展区**：Vygotsky理论——最优学习内容应略高于当前能力
- **认知负荷理论**：Sweller的工作记忆模型——指导多知识点学习时的复杂度加权设计

### 0.6 单用户深度拟合

这是一个只为你服务的系统。它不需要考虑"通用模型"，不需要为了市场迎合任何人的使用习惯。

- 所有算法参数都可以做到极致的个性化
- 所有界面和交互都可以按你的偏好来设计
- 所有数据完全归你所有——存储在你自己控制的GitHub仓库中

**这是一个"为自己做的工具"所能达到的极致：它不是最好的学习系统，但它是最适合你的学习系统。**

### 0.7 设计目的

**量化"学会"的模糊边界：**
- 温度（0-100）：衡量知识点的"记忆热度"
- 掌握度（0-100）：衡量技能的"综合掌握水平"
- 半衰期（天）：衡量知识的"记忆持久力"
- 经验值：学习效率、学科难度、进步速度的综合反映

**用有限时间做最优决策：**
- 智能复习推荐（背包算法求解最优组合）
- 复习时机优化（80%保留率阈值）
- 提分潜力诊断 + 假性熟练检测
- 考试周期建议

**构建"成长可见"的正向循环：**
- 技能掌握度渐进式攀升
- 月度学习报告
- 60+成就覆盖五个维度
- 统计可视化（时间/学科/效率/时段）

**整合"学习"与"生活"的数据边界：**
- 阅读系统（v1.2.0）：追踪阅读时长、分类分布
- 番茄钟系统（v1.1.0）：追踪专注时长、中断率
- 未来扩展：锻炼记录、睡眠追踪等

## 1. 项目总览

### 1.1 项目定位

**一句话定义：** 单用户纯前端自适应学习追踪系统，基于艾宾浩斯遗忘曲线，通过游戏化机制（RPG元素）激励持续学习。

**核心价值排序：**
1. **可视化**（最重要）— 学习成果直观展示
2. **智能推荐** — 基于算法的复习建议
3. **遗忘预警** — 知识点温度监控

|------|------|
| 前端 | 纯 HTML5 + CSS3 + JavaScript (ES6+) |

| 托管 | GitHub Pages |
| 数据 | GitHub Raw + LocalStorage 双缓存 |
| 辅助 | 微信AI (ClawBot) 辅助数据录入 |

## 3. 核心算法

### 3.1 温度模型（知识保留度）

**公式：**
```
T(t) = T_peak × 2^(-t / t_half)
```

| 变量 | 说明 | 范围 |
|------|------|------|
| T(t) | t时刻的温度 | 0-100 |
| T_peak | 最近复习后的峰值温度 | 0-100 |
| t | 距离上次学习的天数 | ≥0 |
| t_half | 动态半衰期（天） | 0.5-30 |

**温度等级：**

| 温度 | 等级 | 颜色 |
|------|------|------|
| 80-100 | 炙热 | #FF4500 |
| 60-79 | 温热 | #FF8C00 |
| 40-59 | 温暖 | #FFD700 |

### 3.2 动态半衰期算法

**三层因子模型：**
```
t_half = t_base × f_subject × f_accuracy × f_streak
```

| 因子 | 计算方式 | 范围 |
|------|----------|------|
| t_base | 全局基础半衰期 | 2-5天 |
| f_subject | 学科修正系数 | 0.7-1.2 |
| f_accuracy | 正确率修正 | 0.8-1.3 |
| f_streak | 连续学习修正 | 0.9-1.2 |

**边界保护：**
- 最小值：0.5天
- 最大值：30天

### 3.3 学科等级算法

**公式：**
```
S = B^0.3 × D^0.4 × E^0.3
```

| 变量 | 说明 |
|------|------|
| S | 学科综合评分 |
| B | 知识广度（已学知识点占比） |
| D | 知识深度（平均温度） |
| E | 学习效率（平均正确率） |

### 3.4 XP计算引擎

**基础公式：**
```
XP = round(score × duration / 20)
```

**边界保护：**
- 除零保护：`Math.max(0.01, ...)`
- 最小XP：1

### 3.5 阴影队列（复习推荐）

**urgency指标：**
```
urgency = (80 - currentTemp) × examWeight / daysUntilExam
```

**推荐优先级：**
```
priority = urgency × subjectLevel × lastReviewDays
```

### 3.6 XP计算引擎（V0.8.0+）

**核心公式：**
```
XP = round(rawXP × qual × decay × softCap)
rawXP = practiceBase × PE + reviewBase × CE × 1.3
qual = E × subjectDifficulty × (1 + momentum) × activityWeight × talentMultiplier
decay = 1 / (1 + totalXP × decayRateForXP)
```

**计算流程：**
1. **推断时间**：将duration分离为practice和review时间
2. **计算效率**：做题效率(PE) + 订正效率(CE) → 综合效率(E)
3. **基础产出**：practiceBase + reviewBase × 1.3（订正价值系数）
4. **质量乘数**：效率 × 学科难度 × (1+进步动量) × 活动权重 × 特长加成
5. **考试特殊处理**：根据难度和历史表现加权
6. **全局调节**：边际递减 × 每日软上限

**关键子算法：**
- **进步动量**：最近10条记录的准确率线性回归斜率，经tanh压缩到[-0.3, 0.3]
- **学科难度**：sqrt(1 / subjectModifiers[subject])
- **每日软上限**：当日XP超过dailyXPLimit后，超出部分乘以softness折扣

### 3.8 三层技能体系（V0.9.0+）

**结构：** 学科(Subject) → 技能(Skill) → 知识点(Knowledge Point)

**知识点→技能聚合：**
```
技能掌握度 = 平均温度×0.5 + 平均正确率×0.3 + 掌握占比×0.2
掌握占比 = 温度≥60的知识点数 / 知识点总数
```

**技能→学科聚合：**
```
学科能力值 = Σ(技能掌握度 × 考试权重) / Σ(考试权重)
```

**技能级特长判定：**
- 条件1：技能掌握度 > 学科平均掌握度 + 15
- 条件2：技能平均半衰期 > 学科平均半衰期 × 1.2
- 同时满足则标记为特长，XP额外×1.1

### 3.9 智能复习推荐（V0.10.0+）

**复习收益计算：**
```
benefit = (80 - currentTemp) × examWeight
```

**0/1背包算法：** 在给定时间预算内，选出总收益最大的知识点组合。

**提分潜力诊断：** 找出掌握度低、考试权重高、近期投入少的技能。

**假性熟练检测：** 连续高正确率但极低订正时间 → 标记"深度检测"。

## 8. V3.0 重构路线图（2026-05-17 制定）

### 8.1 当前状态诊断

**代码健康度：C级（需要重构）**

| 维度 | 评分 | 问题 |
|------|------|------|
| 可维护性 | D | 12K行单文件HTML，212个函数全内联，查找Bug如大海捞针 |
| 稳定性 | C | 存在SyntaxError（已修复1处），初始化链路脆弱 |

| 移动端体验 | C | 导航栏刚修复，多处布局未适配 |
| 系统联动 | C+ | 番茄钟→记录已联动，教辅→知识点缺失，网课→时长缺失 |

**功能审计结果（20项）：**
- ✅ 已实现：18项（温度模型、半衰期、XP引擎2.0、技能树、搜索、推荐、分析、命令面板、番茄钟、阅读、PWA、深色模式、导航栏×2、教辅加载、网课加载、番茄联动、enterMain）
- ⚠️ 部分实现：1项（成就系统23/55，缺少32项检测逻辑）
- ❌ 未实现：1项（教辅选择→知识点自动填充联动）

### 8.2 重构原则

1. **渐进式重构** — 每次改动后页面必须可运行，不追求一次性完美
2. **先修Bug再重构** — 保证基础功能可用后再优化结构
3. **先减后加** — 先删除死代码和冗余，再添加新功能
4. **手机端优先** — 用户主要使用场景是手机，每次改动后手机端验证
5. **联动是核心** — 番茄钟→学习记录→技能树→成就必须形成闭环
