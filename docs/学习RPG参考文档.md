## 1. 设计哲学与设计目的

### 1.1 核心信条：学习的"白箱化"

传统学习是一个黑箱。你投入时间，产出某种"感觉"——觉得自己掌握了、觉得自己退步了、觉得今天效率很高。但这些都是主观判断，缺乏可验证的量化锚点。

**学习RPG的根本哲学是：学习过程可以被量化，而且这种量化能反过来指导学习本身。** 每一次刷题、每一次背诵、每一次考试，都是关于"你如何学习"的实验数据。系统不告诉你"应该学什么"，而是告诉你"你学得怎么样"，让你自己做出更明智的决策。

这不是一个教学系统，而是一个**认知镜面**——它试图照见你学习过程中那些肉眼看不见的变化：一个知识点的记忆是如何衰减的、一个技能是如何从"入门"走向"精通"的、今天的专注投入是否真的转化为了长期记忆。

### 1.2 五大设计原则

#### 原则一：数据溯源闭包原则
系统中任何非用户直接输入的数值，都必须能从历史记录中推导得出。

- 不存在"天降神参"——所有算法权重都由用户的数据决定
- 不存在"预设学科难度"——学科难度的评估完全来自用户在该学科的遗忘速率和正确率表现
- 不存在"固定的每日学习上限"——上限由用户过去30天的实际学习容量动态计算

冷启动时可以使用基于认知科学文献的弱先验（如初始半衰期3天、初始能力值50），但这些先验被设计为可退化的——数据积累后，先验的权重指数级下降，最终完全被个人数据替代。

#### 原则二：低输入负担原则
一个学习系统如果要求用户花大量时间记录，就会陷入"为了记录而学习"的悖论。

- **能不输入的，绝对不让用户输入**——通过教辅联动、章节映射、时间推断，自动补全90%的字段
- **能推断的，绝对不要求精确**——通过个人习惯学习、正确率偏差微调，在缺失数据时做出合理估计
- **能从历史学的，绝对不预设固定值**——订正时间占比、最优学习时长、最佳复习时机，全部从用户数据中学习

**目标：** 用户每日记录投入不超过30秒。理想状态下，5秒完成一条记录。

#### 原则三：自适应而非预设
学习RPG采用自适应模型——从用户的数据中学习用户的规律。

- 半衰期不是固定的1.5天，而是从用户每次复习的间隔和正确率中反推的个性化中位数
- 学科难度不是预设的标签，而是从各科知识点的实际半衰期对比中动态计算
- 每日容量不是500XP的硬编码，而是从过去30天学习时长的80分位数自动得出
- 订正时间占比不是20%的猜测，而是从用户偶尔明确标注的数据中学到的个人习惯

**系统越用越懂你，因为每一次记录都在训练它。**

#### 原则四：认知科学驱动
所有核心算法都有认知心理学文献的支撑：

- **遗忘曲线**：基于艾宾浩斯1885年实验的指数衰减模型（Murre & Dros, 2015 复制验证）
- **间隔重复最优时机**：复习触发阈值设定在保留率降至80%时（Wozniak & Gorzelanczyk 数学推导）
- **测试效应**：检索练习比重复学习更有效（Roediger & Karpicke, 2006）
- **必要难度理论**：Bjork提出——学习过程中付出的认知努力越大，长期记忆越牢固
- **最近发展区**：Vygotsky理论——最优学习内容应略高于当前能力
- **认知负荷理论**：Sweller的工作记忆模型——指导多知识点学习时的复杂度加权设计

#### 原则五：单用户深度拟合
这是一个只为你服务的系统。它不需要考虑"通用模型"，不需要为了市场迎合任何人的使用习惯。

- 所有算法参数都可以做到极致的个性化
- 所有界面和交互都可以按你的偏好来设计
- 所有数据完全归你所有——存储在你自己控制的GitHub仓库中

### 1.3 设计目的：量化"学会"的模糊边界

| 度量 | 范围 | 含义 |
|------|------|------|
| 温度（Temperature） | 0-100 | 知识点的"记忆热度"——现在还记得多少 |
| 掌握度（Mastery） | 0-100 | 技能的"综合掌握水平"——理解+记忆+应用 |
| 半衰期（Half-Life） | 0.5-30天 | 知识的"记忆持久力"——多久会忘掉一半 |
| 经验值（XP） | 累积 | 学习效率、学科难度、进步速度的综合反映 |

**用有限时间做最优决策：**
- 智能复习推荐（背包算法求解最优组合）
- 复习时机优化（80%保留率阈值）
- 提分潜力诊断 + 假性熟练检测
- 考试周期建议

**构建"成长可见"的正向循环：**
- 技能掌握度渐进式攀升
- 月度学习报告
- 60+成就覆盖五个维度
- 统计可视化（时间/学科/效率/时段）

**整合"学习"与"生活"的数据边界：**
- 阅读系统：追踪阅读时长、分类分布
- 番茄钟系统：追踪专注时长、中断率
- 未来扩展：锻炼记录、睡眠追踪等

## 2. Legado 3.0 设计语言集成

### 2.1 Legado 3.0 简介

**gedoor/legado** 是 GitHub 上 38.5k+ Star 的开源 Android 阅读应用，截至2026年4月仍在活跃更新（最后提交 2026-04-27，6558次提交）。它是中文开源社区最知名的阅读器之一。

### 2.2 Legado 3.0 核心设计特征

| 特征 | 描述 | 在本项目中的应用 |
|------|------|-----------------|
| **Material Design 基础** | Google Material Design 2/3 设计语言 | 卡片阴影、涟漪效果、圆角系统 |
| **书架视图** | 列表书架 + 网格书架自由切换 | 概览页学科卡片网格 / 列表切换 |

| **深色模式** | 内置夜间模式 | data-theme="dark" 全局切换 |
| **自定义主题** | 字体、颜色、背景可定制 | CSS变量驱动的主题系统 |
| **搜索栏** | 顶部搜索入口 | 全局命令面板 Ctrl+K |
| **卡片式布局** | 书籍以卡片形式展示 | 学科卡片、记录卡片、成就卡片 |
| **浮动操作按钮** | FAB 悬浮按钮 | 番茄钟悬浮小圆按钮 |

**字段完整说明：**

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | string | 是 | UUID | 记录唯一ID |
| timestamp | string | 是 | now | ISO 8601格式 |
| subject | string | 是 | - | 学科名称（9学科之一） |
| textbook | string | 否 | "" | 教材名称 |
| chapter | number | 否 | 0 | 章节序号 |
| section | string | 否 | "" | 节名称 |
| knowledgePoints | string[] | 否 | [] | 知识点列表 |
| score | number | 是 | 0 | 得分/正确率 0-100 |
| duration | number | 是 | 0 | 总学习时长（分钟） |
| practiceDuration | number | 否 | duration×0.8 | 做题时长（分钟） |
| reviewDuration | number | 否 | duration×0.2 | 订正时长（分钟） |
| activityType | string | 否 | "practice" | 活动类型 |
| totalQuestions | number | 否 | 0 | 总题数 |
| correctCount | number | 否 | 0 | 正确题数 |
| source | string | 否 | "web" | 数据来源 |
| notes | string | 否 | "" | 备注 |

**活动类型枚举：**
- `practice` — 做题练习
- `exam` — 考试/测验
- `lecture` — 听课/看网课
- `review` — 复习
- `recitation` — 背诵/默写
- `reflection` — 考试反思
- `reading` — 阅读
- `other` — 其他

## 5. 核心算法完整规格

### 5.1 温度模型（知识保留度）

**理论基础：** 艾宾浩斯遗忘曲线（Ebbinghaus, 1885）— 指数衰减模型

**公式：**
```
T(t) = T_peak × 2^(-t / t_half)
```

| 变量 | 说明 | 取值范围 | 默认值 |
|------|------|----------|--------|
| T(t) | t时刻的温度（保留度） | 0-100 | - |
| T_peak | 最近复习后的峰值温度 | 0-100 | 80 |
| t | 距离上次学习的天数 | ≥0 | - |
| t_half | 动态半衰期（天） | 0.5-30 | 3.0 |

**温度等级映射：**

| 温度范围 | 等级名称 | 颜色代码 | CSS变量 | 图标 |
|----------|----------|----------|---------|------|
| 80-100 | 炙热 (Searing) | #FF4500 | --temp-searing | 🔥 |
| 60-79 | 温热 (Hot) | #FF8C00 | --temp-hot | 🟠 |
| 40-59 | 温暖 (Warm) | #FFD700 | --temp-warm | 🟡 |
| 20-39 | 正常 (Normal) | #62A0EA | --temp-normal | 🟢 |
| 1-19 | 微凉 (Cool) | #1A5FB4 | --temp-cool | 🔵 |
| 0 | 冻结 (Frozen) | #6B7280 | --temp-frozen | ⚫ |

**复习触发阈值：**
- 温度降至 80 → 建议复习（最佳时机）
- 温度降至 60 → 需要复习
- 温度降至 40 → 紧急复习
- 温度降至 20 → 几乎遗忘，需要重新学习

### 5.2 动态半衰期算法

**公式：**
```
t_half = t_base × f_subject × f_accuracy × f_streak
```

**约束：** max(0.5, min(30, t_half))

| 因子 | 名称 | 计算方式 | 范围 |
|------|------|----------|------|
| t_base | 基础半衰期 | user_profile.globalBaseHalfLife | 2-5天 |
| f_subject | 学科修正 | user_profile.subjectModifiers[subject] | 0.7-1.2 |
| f_accuracy | 正确率修正 | 1 + (accuracy - 70) / 100 | 0.8-1.3 |
| f_streak | 连续学习修正 | 1 + min(repetitions, 10) × 0.02 | 1.0-1.2 |

**复习后的半衰期更新：**
```
新半衰期 = 旧半衰期 × (表现好 ? increaseRatio : decreaseRatio)
表现好 = accuracy ≥ 70%
increaseRatio = 1.2
decreaseRatio = 0.75
```

### 5.3 学科等级算法

**公式：**
```
S = B^0.3 × D^0.4 × E^0.3
```

| 变量 | 名称 | 计算方式 |
|------|------|----------|
| S | 学科综合评分 | 0-100 |
| B | 知识广度 | 已学知识点数 / 该学科总知识点数 |
| D | 知识深度 | 该学科所有知识点的平均温度 / 100 |
| E | 学习效率 | 该学科所有记录的平均正确率 / 100 |

**等级称号体系（日语）：**

| 分数范围 | 称号（日文） | 称号（中文） | 颜色 |
|----------|-------------|-------------|------|
| 0-9 | 見習い (Minarai) | 见习 | #9CA3AF |
| 10-19 | 初心者 (Shoshinsha) | 初心者 | #6B7280 |
| 20-39 | 学徒 (Gakuto) | 学徒 | #3B82F6 |
| 40-59 | 熟練者 (Jukurensha) | 熟练者 | #10B981 |
| 60-79 | 達人 (Tatsujin) | 达人 | #F59E0B |
| 80-94 | 名人 (Meijin) | 名人 | #EF4444 |
| 95-100 | 伝説 (Densetsu) | 传说 | #8B5CF6 |

### 5.4 XP计算引擎2.0

**完整公式：**
```
XP = round(rawXP × qual × decay × softCap)

rawXP = practiceBase × PE + reviewBase × CE × 1.3

其中：
  practiceBase = practiceDuration × xpBasePerMinute
  reviewBase = reviewDuration × xpBasePerMinute
  PE = 做题效率 = accuracy / 100
  CE = 订正效率 = min(1, accuracy / 100 × 1.2)

qual = E × subjectDifficulty × (1 + momentum) × activityWeight × talentMultiplier

其中：
  E = PE × (1 - reviewRatio) + CE × reviewRatio × 1.3
  subjectDifficulty = sqrt(1 / subjectModifiers[subject])
  momentum = tanh(regressionSlope(last10Records)) × 0.3
  activityWeight = user_profile.activityWeights[activityType]
  talentMultiplier = 有技能特长 ? 1.1 : 1.0

decay = 1 / (1 + totalXP × decayRateForXP)

softCap = dailyXP >= dailyXPLimit 
          ? 1 - (1 - softness) × (dailyXP - dailyXPLimit) / dailyXPLimit
          : 1
```

**边界保护：**
- rawXP ≥ 0.01（除零保护）
- XP ≥ 1（最小值）
- XP ≤ 500（单条记录最大值）
- 每日XP无硬上限（软上限后可继续获取但打折）

### 5.5 阴影队列（复习推荐）

**urgency指标：**
```
urgency = (80 - currentTemp) × examWeight / max(1, daysUntilExam)
```

**推荐优先级排序：**
```
priority = urgency × subjectLevel × log(1 + lastReviewDays)
```

**背包算法（0/1 Knapsack）：**
```
输入：
  - 待复习知识点列表（每个有 cost=预估复习时间, benefit=复习收益）
  - 时间预算 T（用户可用复习时间）

目标：
  - 在总cost ≤ T 的前提下，最大化总benefit

算法：
  dp[i][t] = max(dp[i-1][t], dp[i-1][t-cost_i] + benefit_i)
```

### 5.6 进步动量

```
收集最近10条记录的正确率序列: [a1, a2, ..., a10]
计算线性回归斜率: slope = regression([1..10], [a1..a10])
压缩到[-0.3, 0.3]: momentum = tanh(slope / 10) × 0.3
```

### 5.7 提分潜力诊断

**诊断逻辑：**
```
对每个技能计算：
  potential = (1 - mastery) × examWeight × (1 - recentInvestment)

其中：
  mastery = 技能掌握度（0-1）
  examWeight = 考试权重（0-1）
  recentInvestment = 近7天在该技能上的学习时长 / 近7天总学习时长

排序：potential 从高到低
展示：Top 5
```

### 5.8 假性熟练检测

**检测逻辑：**
```
IF 技能连续3次正确率 > 85% 
   AND 平均订正时间占比 < 10%
   AND 技能温度 < 60
THEN 标记为 "⚠️ 假性熟练 — 建议深度检测"

说明：高正确率+低订正时间但温度低 → 可能只是短期记忆或运气
      需要更深入的检测（如综合题、变式题）来验证真正掌握
```

### 5.9 用户画像自适应更新

**学科能力值更新（EMA）：**
```
subjectAbility = avgTemp × 0.5 + avgAccuracy × 0.5
```

**学科修正系数更新（EMA，α=0.3）：**
```
subjectModifiers = 0.7 × old + 0.3 × (avgHalfLife / globalBaseHalfLife)
```

**全局半衰期更新（EMA，α=0.2）：**
```
globalBaseHalfLife = 0.8 × old + 0.2 × median(allHalfLives)
```

**XP参数自动校准：**
```
每7天检查一次：
  avgXpPerMinute = 近7天总XP / 近7天总学习分钟数
  IF avgXpPerMinute 偏离 2.0 超过 20%:
    xpBasePerMinute = 0.8 × old + 0.2 × (2.0 / avgXpPerMinute × old)
```

### 5.10 技能聚合算法

**知识点→技能聚合：**
```
技能掌握度 = 平均温度×0.5 + 平均正确率×0.3 + 掌握占比×0.2
掌握占比 = 温度≥60的知识点数 / 该技能知识点总数
```

**技能→学科聚合：**
```
学科能力值 = Σ(技能掌握度 × 考试权重) / Σ(考试权重)
```

**技能特长判定：**
```
条件1：技能掌握度 > 学科平均掌握度 + 15
条件2：技能平均半衰期 > 学科平均半衰期 × 1.2
同时满足 → 标记为特长 → XP额外×1.1
```

## 13. PWA与离线支持规格

### 13.1 Service Worker策略

```
策略：Cache First + Network Update

1. 首次访问 → 缓存所有静态资源
2. 后续访问 → 优先从缓存加载（秒开）
3. 后台静默更新缓存
4. 数据通过GitHub Raw API获取（需网络）

缓存清单：
  - index.html（主应用）
  - css/*.css（样式文件）
  - js/*.js（脚本文件）
  - assets/images/*（图片）
  - data/*.json（数据文件兜底）
```

### 13.2 manifest.json配置

```json
{
  "name": "学习RPG · 认知操作系统",
  "short_name": "学习RPG",
  "description": "游戏化学习追踪系统",
  "start_url": "/learning-rpg/",

  "icons": [
    { "src": "icon.svg", "sizes": "any", "type": "image/svg+xml" }
  ]
}
```

### 13.3 离线降级策略

```
网络不可用时：
  1. 页面正常渲染（从缓存加载）
  2. 数据使用localStorage缓存
  3. 新记录保存到localStorage
  4. 网络恢复后自动同步到GitHub

同步冲突处理：
  - 最后写入者胜出（Last Write Wins）
  - 基于timestamp比较
```
